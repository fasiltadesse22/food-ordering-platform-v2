# C1.2-P20 — Production Diagnosis of Cross-Authority Invariant Failures

Symptom: Order ACCEPTED but missing acceptance history; Order PLACED with acceptance history; aggregate reconstruction raises InvalidPersistedOrderException; or hypothetical inventory allocated beyond capacity.
Scope: OrderId, status, history positions/action, root version, writers/deployment, SQL transaction IDs, prior commands, independent authoritative store refs. Payment provider state must be sourced from provider, never inferred from Order-local PAYMENT_RECORDED.
Timeline: business command -> first authority commit -> gap -> second authority command -> failure/timeout/commit -> read -> replay/recovery. Identify exact commit boundaries and what each observer could know at each moment.
Evidence: real root/history SQL rows, transactions and DB constraints, selected OrderInvariants violations, JVM process history, SQLState, source application command and actor/identity. Do not infer provider capture or remote inventory change from local Order event.
Competing hypotheses: artificial split writes, manual migration/script bypass of OrderRepository, failing child write after independent root commit, legacy binary bypassing version protocol, coherent committed corruption vs P16 torn snapshot, duplicate command, async projection lag, cross-aggregate oversell.
Discriminating test: repeat unsafe status-first and history-first commits against PostgreSQL; compare one-tx old/new coherent reader; reproduce controlled second-stage error; compare inventory unsafe independent insert to conditional shared admission. Record committed vs attempted, not merely exception name.
Mechanism: Local SQL row CHECK cannot express all selected root/history business invariants; separately committed row-valid components can violate required cross-state implication. Rollback of second tx cannot undo first commit. P16 read snapshot sees a coherent snapshot of actually invalid committed state, not a torn read.
Mitigation: stop bypass writers; restore single authoritative transaction for hard local invariant or implement justified equivalent enforcement; assess reconciliation carefully rather than blindly fabricating missing history; protect inventory reserve with its own authoritative allocation condition if business requires zero oversell. Do not combine complete Restaurant or Payment authority with Order by default.
Validation: P20 six actual DB experiments, P15 rollback contract, P16 read snapshot, P17 CAS, P18 retry classification, P12 durable JVM recovery, root Maven CI; monitor malformed state, partial commits, reconciliation backlog, capacity reservation conflicts. No fabricated SLO.
