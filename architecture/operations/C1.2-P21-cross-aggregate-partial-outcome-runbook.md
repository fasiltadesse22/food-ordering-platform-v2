# C1.2-P21 — Cross-Aggregate Partial-Outcome Diagnostic Runbook

Symptoms: Order PLACED without inventory reservation; inventory remaining decremented without Order; duplicate stock allocation; payment charged but local PAYMENT_RECORDED absent; restaurant rejects an unavailable item. Different symptoms have different authorities.
Scope: OrderId, RestaurantId, itemId, quantity, stock authority ID, stock revision if enforced, reservation ID, request/operation ID, provider references when real provider exists, timeline by transaction/remote participant.
Timeline: request -> domain proposal snapshot -> authoritative stock conditional admission -> Order write -> individual COMMIT points -> response -> client retry. Determine which are one physical transaction and which independent.
Hypotheses: stale observed stock, application check-then-write, split Order/stock commits, unknown COMMIT acknowledgement, duplicate client submission, reservation expiration, wrong RestaurantId, underaggregated repeated SKU lines, provider response uncertainty. Do not blame Kafka or assume service boundaries absent actual evidence.
Discriminators: read committed authoritative Order and stock/reservation rows, compare observed planning version to admission, reproduce same shared snapshot with two concurrent SQL tx, inject error after local stock decrement, differentiate known SQL abort vs unknown COMMIT (P15/P18). No absence of local payment fact proves provider did not capture funds.
Mechanism: pure planning decision is advisory; shared stock CAS enforces local admission; one local DB transaction ties Order+stock reservation writes when the business requires strong local atomicity. Independent commits need allowed intermediate states and repair plan, cannot be retroactively rolled back by later tx.
Mitigation: do not blindly retry with fresh OrderId or duplicate reservation; reconcile authoritative local facts and external provider separately, consider stable operation key and idempotent unique reservation ID when business requirements formalized. Treat stock-first orphan capacity differently from Order-first unreserved Order.
Validation: existing P12-P20 correctness checks, P21 six unit + five Testcontainers checks, exact Maven CI, future production-style transaction path only after domain lifecycle specified. Metrics proposals: stock_admission_conflict, orders_without_required_reservation, capacity_consumed_unmatched, unknown_commit_outcome, reconciliation_age, stock hot-key wait. No fabricated SLO.
