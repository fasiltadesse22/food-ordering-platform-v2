## Engineering prediction

Making command outcomes explicit and introducing an OrderPlaced domain fact only on the accepted path will make the distinction between requested intent and accepted business fact executable without introducing messaging infrastructure.

## Structural changes

- PlaceOrderUseCase now returns PlaceOrderResult;
- PlaceOrderResult has Accepted and Rejected variants;
- PlaceOrderRejection makes current rejection reasons explicit;
- OrderPlaced represents the accepted local domain fact;
- PlaceOrderService returns rejection instead of an actor-eligibility exception;
- accepted result contains OrderSnapshot plus OrderPlaced;
- controller maps accepted/rejected application outcomes to HTTP responses;
- actor acceptance tests were evolved to assert result semantics;
- PlaceOrderSemanticFlowTest was added;
- P01 framework-free harness was mechanically updated for the new result type;
- obsolete ActorNotAllowedException was removed;
- ADR-0003 explicitly forbids treating the domain fact as messaging.
