## Requirement

Acknowledged business state whose required lifetime exceeds one process lifetime needs a durable recovery source consistent with the required failure model.

## Structural facts

- InMemoryOrderRepository stores Orders only in a process-owned ConcurrentHashMap;
- no database/file/external durable store is used;
- a new repository starts empty;
- startup contains no Order-state recovery path.

## Executed and verified conclusions

### Authority

Before crash, the running application was authoritative for the selected Order and returned CANCELLED.

### Process loss

SIGKILL removed the JVM that owned that authority.

### Restart

A new JVM restored the application process and HTTP capability.

### Business-state recovery

The selected previously acknowledged Order was absent and returned 404.

## Evidence-backed inference

authoritative-now != durable.

saveCurrent success != crash/restart durability.

HTTP 201/200 acknowledgement != durable commit.

process restart != business-state recovery.

availability of a new process != durability of prior business state.
