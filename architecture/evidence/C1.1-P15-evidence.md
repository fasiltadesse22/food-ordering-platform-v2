## Structural claim

OrderWorkflowUseCase identifies the target Order and relevant actor, but accepts no logical command identifier/idempotency key.

Therefore current code has no explicit way to classify two same-looking calls as:
- replay of one logical command; or
- separate commands with the same payload.

## Requirement

Repeated delivery of one logical command must not multiply any business effect that is required to occur once.

If caller recovery relies on retry, the contract must also define replay-result semantics.

## Required distinctions verified by evidence

effect convergence != duplicate detection.

duplicate suppression != original-result replay.

same final state != at-most-once execution.

state-machine rejection on replay != replay-aware idempotency.

semantic prior-effect guard != general idempotency store.

## Evidence-backed inference

Current cancellation behavior is locally effect-convergent under the selected sequential state-machine path, but this cannot be generalized to operations with external independently committed effects.

The current refund guard suppresses a second local workflow occurrence but provides no durable replay identity across restart.

## Explicit non-guarantees

- no logical command identity;
- no at-most-once execution;
- no durable duplicate detection;
- no exactly-once external effect;
- no original-result replay;
- no retention/expiry semantics;
- no same-key/different-payload conflict semantics;
- no restart-safe idempotency.

## Preserved fragile state

The platform remains deliberately pre-idempotent.

This exact state is required for:
- P16 duplicate-payment/external-effect reasoning;
- the later dedicated idempotency cluster.
