## Executed observations

1. `PLACED`, `ACCEPTED`, `PREPARING` classify active fulfillment.
2. `REJECTED`, `CANCELLED`, `COMPLETED` classify terminal fulfillment.
3. A rejected/cancelled Order without prior local payment milestone cannot record refund request under the selected policy.
4. A paid locally recorded rejected/cancelled Order may append **one** refund-request occurrence without reopening terminal fulfillment.
5. A second request is denied; exactly one existing request occurrence remains.
6. The prior `PAYMENT_RECORDED` occurrence is preserved when `REFUND_REQUESTED` is appended.
7. A completed Order cannot be cancelled or reaccepted.
8. A rejected/cancelled Order cannot resume preparation or completion.
9. Exposed `lines()` and `workflowOccurrences()` lists are immutable; attempted in-place mutations fail. **There is no generic edit business command**, so no test of a hypothetical `modifyOrder` permission was claimed.
10. Calling `closure()` is a pure read-only assessment, not a state change.
11. Completed paid Order has no automatic `REFUND_REQUESTED` path in current policy.
12. Existing P01–P07 Java and integration cases remained green in the 63-test suite.

## Claim boundaries

- `PAYMENT_RECORDED` ≠ actual provider capture or settlement.
- `REFUND_REQUESTED` ≠ provider refund, guaranteed financial compensation, customer funds returned or a Saga operation.
- `NO_LOCAL_PAYMENT_EVIDENCE` ≠ certainty that no charge happened elsewhere.
- New code does not modify provider money, transaction balances, restaurant physical behavior or other independently authoritative resources.
- Domain occurrence history is an in-memory immutable copy, **not durable append-only storage**.
- The current repository is not concurrent read–guard–save atomic. Duplicate local requests are only sequentially denied when the existing request is visible to the caller.
- The current app has no public authenticated workflow action endpoints or edit-order operation.
- No PostgreSQL, Kafka, Saga, Outbox, provider status inquiry, idempotent external refund execution, reconciliation or crash recovery introduced.
