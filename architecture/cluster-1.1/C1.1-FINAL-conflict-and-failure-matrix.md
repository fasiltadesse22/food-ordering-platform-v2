## Cross-cutting lesson

The current application contains multiple independent correctness dimensions:

- semantic validity;
- lifecycle legality;
- contextual authorization/guarding;
- representation invariants;
- atomic publication;
- concurrent history validity;
- replay/effect identity;
- external-authority consistency;
- temporal freshness;
- durability/recovery.

Passing one dimension never proves the others.

## Simpler alternatives retained

Before adding stronger mechanisms, alternatives include:
- preserve one single deployable;
- use local transaction/DB versioning once one DB is authority;
- treat naturally convergent commands differently from financial effects;
- reject stale commands rather than blindly merge;
- keep external effects synchronous until evidence justifies asynchronous messaging.

## Over-engineering failures explicitly rejected in Cluster 1.1

No evidence currently justifies adding:
- Kafka;
- Redis distributed locks;
- Saga;
- Outbox;
- CQRS;
- Event Sourcing;
- service mesh;
- database-per-service;
- Kubernetes/autoscaling.

Those may become justified later by different forces.
