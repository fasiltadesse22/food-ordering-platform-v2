# C1.1-P06 — State Machines and Legal/Illegal Transitions

## Engineering question

Which lifecycle transitions are valid, and which must be impossible?

## Derived lifecycle

The P06 Order lifecycle is:

PLACED
  ├→ ACCEPTED
  │    └→ PREPARING
  │          └→ COMPLETED
  ├→ REJECTED
  └→ CANCELLED

## Legal transition table

| Transition operation | Source | Target | Workflow occurrence |
|---|---|---|---|
| ACCEPT | PLACED | ACCEPTED | RESTAURANT_ACCEPTED |
| REJECT | PLACED | REJECTED | RESTAURANT_REJECTED |
| CANCEL | PLACED | CANCELLED | ORDER_CANCELLED |
| START_PREPARATION | ACCEPTED | PREPARING | PREPARATION_STARTED |
| COMPLETE | PREPARING | COMPLETED | ORDER_COMPLETED |

Any invocation of one of these operations from another source state is illegal in P06.

## Important distinction: trigger/action != state

RESTAURANT_ACCEPTED is a workflow occurrence associated with the transition.

ACCEPTED is the resulting lifecycle state.

An occurrence answers "what happened?"

A state answers "what lifecycle condition is true now?"

## Important distinction: workflow != state machine

P05 could record:

PAYMENT_RECORDED
→ RESTAURANT_ACCEPTED
→ PREPARATION_STARTED
→ ORDER_COMPLETED

P06 maps only the fulfillment-relevant milestones into lifecycle transitions.

PAYMENT_RECORDED does not change OrderStatus.

REFUND_REQUESTED does not change OrderStatus.

This preserves separate state dimensions rather than creating one giant enum.

## Rejection semantics

An illegal transition:
- throws IllegalOrderTransitionException;
- does not create a new Order representation;
- does not append the attempted workflow occurrence;
- does not update the repository because OrderWorkflowService never receives an updated Order.

This is transition legality evidence.

It is not yet the complete business-failure taxonomy.

## P06 illegal examples

Rejected:
- PLACED → START_PREPARATION
- ACCEPTED → REJECT
- ACCEPTED → COMPLETE
- REJECTED → ACCEPT
- CANCELLED → START_PREPARATION
- COMPLETED → ACCEPT

The project executes selected examples rather than attempting every theoretical pair.

## What P06 deliberately does not decide

P06 does not yet deeply define:
- guards based on payment or actor context;
- preconditions/postconditions;
- terminality;
- reversibility;
- compensation;
- duplicate/repeated-command semantics;
- concurrency/stale-state behavior.

The state machine is therefore a lifecycle skeleton whose state-source legality is executable.
