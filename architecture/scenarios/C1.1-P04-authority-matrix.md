# C1.1-P04 — Authority Matrix

| Representation | What it tells us | Current authority? | Can become stale? |
|---|---|---|---|
| OrderId | Which logical Order is referenced | Identity reference, not state authority | No state to become stale |
| Order Java object | One in-memory representation of Order state | Only when selected as repository current state | Yes, if detached/replaced |
| OrderRepository current mapping | Current in-process Order state | Yes, within current application scope | Itself is current by definition |
| OrderSnapshot | Point-in-time application observation | No | Yes |
| OrderResponse | Point-in-time HTTP representation | No | Yes immediately after response |
| OrderPlaced | Fact that placement was accepted | Historical semantic fact, not current state | Not "stale"; it answers a different question |
| Order total | Derived from current lines | Derived, not independently authoritative | A copied value can become stale |
| Future DB row | Not present yet | Undecided until Cluster 1.2 | Depends on later persistence model |

## Rule

Always ask "authoritative for what?"

A component or record can be authoritative for one question and irrelevant for another.

The Order repository is current authority for Order state in this process. It is not authority for payment-provider truth or restaurant menu availability.
