# C1.1-P15 — Lost Response Then Retry

```text
Customer                 Application                 Authority
   |                          |                          |
   | CANCEL ---------------->|                          |
   |                          |---- read -------------> |
   |                          |<--- PLACED ------------ |
   |                          |                         |
   |                          | derive CANCELLED        |
   |                          |---- save -------------> |
   |                          |                         | CANCELLED
   |                          |<--- save returns -------|
   |        X response lost   |                          |
   |< - - - - - - - - - - - |                          |
   |                          |                          |
   | CANCEL retry ----------->|                          |
   |                          |---- read -------------> |
   |                          |<--- CANCELLED ---------- |
   |                          |                         |
   |<-- ILLEGAL_TRANSITION ---|                          |
```

## Knowledge

After the response loss:

Application authority:
knows/contains CANCELLED.

Customer:
knows only that no success response was received.

A timeout/lost response is therefore not proof that the original command failed.

## Current replay limitation

The retry has no logical command identity that lets the server say:
"This is the same cancellation I already accepted; here is its original result."

The lifecycle merely sees a new CANCEL attempt against CANCELLED.
