# C1.1-P18 — Process Boundary and State Lifetime

```text
                  PROCESS A
+---------------------------------------------+
| Spring Boot JVM                             |
|                                             |
|  HTTP -> application -> OrderRepository     |
|                         |                   |
|                         v                   |
|                 ConcurrentHashMap           |
|                 O123 -> CANCELLED           |
+---------------------------------------------+
                    |
                    | SIGKILL
                    v
             process memory gone

                  PROCESS B
+---------------------------------------------+
| new Spring Boot JVM                         |
|                                             |
|  new InMemoryOrderRepository                |
|                         |                   |
|                         v                   |
|                 new ConcurrentHashMap       |
|                 (empty)                     |
|                                             |
| GET /orders/O123 -> 404                     |
+---------------------------------------------+
```

## What survived

- executable artifact;
- source/build artifact outside the application process;
- CI logs/evidence.

## What did not survive in the current runtime design

- process A's in-memory Order map.

## Key lesson

Restarting compute restores execution capacity.

It does not reconstruct business state unless that state has a durable recovery source.
